# subconverter 优化分析

日期：2026-10-01。分析基线：fork `cee62a3`，原项目 `a0d4eab`。

## 已确认目标

- 使用范围：本机和自己的局域网设备。
- 优化重点：稳定性与排障、使用体验、性能。
- 维护方式：逐步形成自己长期使用的独立版本。
- 平台：Windows 为主，同时保留 Linux/Docker。
- 使用方式：先保留 URL 和配置文件，增加检查与诊断；后续 Web 参考 ACL4SSR 与 histion 的转换前端。
- 性能场景：通常一份订阅，最多两份；主要慢在首次转换，后台持续运行后其他设备使用更顺畅。
- 实际外部配置：yxymeng.github.io 的 `Ruleset/Clash.ini`。
- 规则更新取舍：需要更新时等待完成，优先最新。
- Web 第一版：转换表单、配置预设、诊断、结果预览和复制链接。
- 缓存语义：有效期内复用；过期或主动强刷时等待更新。
- 更新失败：必需规则集失败时明确报错，保留旧版供手动选择。

访谈中的目标与取舍已经明确。建议实施顺序、各阶段范围和验收场景见 [优化路线](optimization-roadmap.md)；本轮已按此路线实施，原基线分析作为问题证据保留；当前行为与验收见 [实施记录](implementation-validation.md)。

术语见 [GLOSSARY.md](../GLOSSARY.md)。特别区分订阅源、原始订阅、节点协议、目标格式和外部配置；“HTTP 200”“解析得到节点”“目标客户端接受输出”是不同的成功条件。

## 建议方向与证据

### 1. 优先补齐订阅下载的可靠性与诊断

这次 403 修复解决了真实的源站兼容问题，也说明下载行为是最值得持续投入的边界。

| 现有行为 | 证据与验证程度 | 建议 |
| --- | --- | --- |
| 下载失败和无有效节点的提示混在一起 | [FetchResult](../src/handler/webget.h) 只保留 HTTP 状态码；[curlGet](../src/handler/webget.cpp) 丢弃传输错误；[调用层](../src/handler/interfaces.cpp) 返回泛化的节点错误。已核对源码。 | 保留传输结果、HTTP 状态、错误阶段、耗时和有限的错误摘要；区分下载失败、内容无法解析和没有可导出的节点。 |
| 中断重试会拼接第一次残留和第二次正文 | [curlGet](../src/handler/webget.cpp) 的 writer 持续追加，重试之间未重置缓冲。已在抽取原函数的本地 HTTP 检查中复现：`PARTIALCOMPLETE`，正确正文应为 `COMPLETE`。 | 每次尝试使用独立缓冲，成功后提交正文；按请求方法和错误类型决定是否重试。 |
| HTTP 200 的传输失败可能覆盖旧缓存 | 下载失败时正文被清空，但 [缓存更新](../src/handler/webget.cpp) 只检查 HTTP 200。已复现“200 + 空正文”；覆盖缓存的结论来自源码控制流，尚未跑完整缓存路径。 | 成功同时要求传输完成和可接受的 HTTP 状态；失败保留旧缓存，并让缓存回退可观察。 |
| 客户端的部分请求头仍被转发到订阅源 | 默认入口已过滤 Host、Accept、Accept-Encoding 和 LOCAL_/REMOTE_；[接口](../src/handler/interfaces.cpp) 仍将剩余请求头交给 [节点下载](../src/generator/config/nodemanip.cpp)。Authorization、Cookie、Connection 等会被继续传递。已核对默认路径。 | 区分客户端请求头与订阅源请求头；保留合理的 UA 兼容能力，源站凭据按来源配置，过滤逐跳请求头。 |
| 移除内部标记后，现有循环检测无法识别本转换器请求 | [服务端循环检测](../src/server/webserver_httplib.cpp) 仍只识别 SubConverter-Request。上一轮抽取函数检查已确认上游请求被拒绝、fork 请求可以通过。 | 保留这次 403 修复，另行确定允许的转换器串联范围，并设计自引用与循环引用的限制。 |

第一阶段的验收用例宜包含：403、200 无效内容、下载中断、重试成功、代理失败、超时、保留自定义 UA、失败时使用旧缓存。测试使用虚构订阅与本地模拟源站。

诊断应默认遮盖订阅 Token、Cookie 和认证信息。当前 [日志入口](../src/server/webserver_httplib.cpp) 会打印完整请求地址与头，[订阅处理](../src/handler/interfaces.cpp) 也会记录完整源 URL；直接提高日志级别会扩大敏感信息暴露。

### 2. 让本机与局域网使用更容易理解

已有能力包括首次自动复制配置、UTF-8 控制台、指定配置文件、配置档案和日志重定向，不必重复实现。

可优先增加一次诊断入口，显示实际配置路径、监听地址、版本与提交、订阅/配置/规则集各自的代理选择，并检查端口和依赖配置。诊断订阅时只显示脱敏地址、HTTP 状态和失败阶段。

需要协调的现有默认值：

- [示例配置](../base/pref.example.toml) 的订阅下载使用 NONE，配置和规则集使用 SYSTEM；这三条链路可能采用不同代理。
- 示例监听 `0.0.0.0`，README 的本机建议则为 `127.0.0.1`；应提供明确的本机与局域网配置方式。
- 示例启用详细日志。应让普通使用和临时诊断的日志行为清晰，并共同采用脱敏规则。

用户选择先补诊断，后续再加入 Web。Web 应复用已有转换接口，并明确页面的监听范围、局域网访问方式以及订阅凭据存放位置。

两个参考站点的公开源码已核对：

- [ACL4SSR 转换前端](https://github.com/acl4ssr-sub/acl4ssr-sub.github.io)：基础/进阶模式、多订阅、客户端与远程配置选择、筛选、复制链接、一键导入；当前版本还有从已有 URL 还原参数。
- [histion 转换前端](https://github.com/histion/clash/tree/master)：同类转换表单、配置选择、参数和复制/导入操作。

源码中的 makeUrl 在浏览器构造 `/sub` 链接，抓取、解析和导出仍由后端完成。参考实现的 localStorage 记忆输入不能等同于服务端保存、跨设备同步或固定分享档案。第一版可借鉴表单与预设，同时复用先期建设的诊断结果；生成链接成功与实际转换成功应分别展示。

本轮读取了入口与 source map 中的表单源码，没有运行或查看参考站点 UI。短链和配置上传依赖额外服务，当前第一版范围未包含这两项。

### 3. 按真实耗时优化性能

已确认的结构事实：

- [订阅合并](../src/handler/interfaces.cpp) 顺序调用 addNodes，多个慢源会累计等待时间。
- [curlGet](../src/handler/webget.cpp) 每次创建并销毁句柄，超时固定为 15 秒；连接复用的实际收益尚未测量。
- [缓存](../src/handler/webget.cpp) 只保护文件读写，没有合并同一过期键的并发下载。
- 缓存键只包含 URL。如果同一 URL 按 UA 或认证信息返回不同内容，可能复用错误的版本；该影响取决于源站行为。
- 项目已有服务端线程池、规则集缓存与异步选项；仅增加线程数可能放大源站限流。

用户通常只有一两份订阅，主要痛点是首次转换。因此基线应优先区分首次下载、缓存命中和缓存过期后的转换，再记录订阅下载、外部配置、规则下载、规则处理和导出的耗时。基准中应包含正常源、慢源和失败源。

候选措施是有上限的并发规则下载、保持规则优先顺序、规则内容及处理结果缓存、同缓存键的请求合并、连接复用以及合理的缓存键。仅对订阅源增加并发不会覆盖几十个规则源的成本。不承诺未经测量的优化收益。

#### yxymeng.github.io 的具体线索

本轮只读检查了已存在的本地 yxymeng.github.io 仓库，没有拉取或修改它。用户已确认实际使用 `Ruleset/Clash.ini`。

| 配置或规则文件 | 本地快照的实际规模 |
| --- | --- |
| Ruleset/Clash.ini | 25 个不同的远程规则文件引用 |
| Ruleset/ClashFA.ini | 24 个不同的远程规则文件引用 |
| Ruleset/Merged/ads.list | 2,949,074 字节，87,196 行 |
| Ruleset/Merged/Chinaip.list | 593,848 字节，17,307 行 |
| Clash.ini 引用的本仓库规则文件总计 | 3,557,593 字节，105,007 行；不含引用的其他仓库文件 |

这是文件行数，包含注释或空行，不等于最终输出规则条数。只有被转换配置引用的内容进入加载链；仓库中无关文件的数量不会自动增加单次转换工作量。

默认示例 `async_fetch_ruleset=false`；[refreshRulesets](../src/handler/settings.cpp) 经 [fetchFileAsync](../src/handler/multithread.cpp) 逐项等待。若实际配置沿用默认值且需要远程下载这 25 个文件，首次耗时可能累积。

[rulesetToClashStr](../src/generator/config/ruleconvert.cpp) 每次生成仍读取并处理规则内容，当前下载缓存不能等同于完整输出缓存。应测量网络等待与规则处理各自占比，再选择：启用现有异步规则下载进行对照、补有上限的下载并发、预热常用规则、缓存按内容和配置版本区分的规则处理结果。

完整转换结果缓存是后续候选。缓存键必须区分目标格式、有效参数、订阅内容版本、规则与配置版本以及影响结果的请求身份；更新成功后让相关结果失效，并验证转换输出和规则匹配顺序保持一致。

### 4. 保证发布包确实包含 fork 的改动

这是源码已确认的发布问题：[Docker 工作流](../.github/workflows/docker.yml) 使用上游镜像名，构建上下文仅为 scripts；[Dockerfile](../scripts/Dockerfile) 又重新克隆原项目。因此修复 Docker 登录本身并不能保证镜像包含这次 403 修复。

若继续使用 Docker，镜像应从当前 checkout 构建，版本能追溯到实际源码提交，使用说明指向本 fork 的产物。

现有 CI 覆盖多个平台编译，但没有发现本项目的行为测试套件；部分构建依赖仍从未固定的仓库 HEAD 获取。长期独立维护宜补上少量关键行为回归、发布包启动与转换冒烟检查，并固定影响构建结果的依赖版本。

### 5. 将转换质量作为可靠性的一部分

新增协议当前不是用户选定的优先方向，但已有协议的字段保真与错误报告仍影响稳定使用。

以下问题来自源码推导，尚未运行完整转换程序复现：

- AnyTLS 已支持解析与部分导出，但 [类型分组匹配](../src/generator/config/subexport.cpp) 的类型表遗漏它；遇到 `!!TYPE=` 规则会抛异常，使请求失败。
- Hysteria2 [构造](../src/parser/subparser.cpp) 写入 UpSpeed/DownSpeed，但部分 [导出](../src/generator/config/subexport.cpp) 用未填充的 Up/Down 判断是否输出速率。
- Trojan 的 TLS SNI 与 WebSocket Host 共用内部字段，输入两个不同值时，部分转换路径不能分别保留。
- Hysteria/Hysteria2 的部分 Clash ALPN 解析路径只保留列表首项。

目标格式不支持某节点时，应报告输入数、输出数和过滤原因。现有 `mixed` 只导出 SS、SSR、VMess 和 Trojan，输入支持某协议不能推导出所有目标都支持。

这些适合作为小型脱敏回归样本；是否进一步增加 VLESS、TUIC 或更多目标能力，应根据实际订阅再决定。

### 6. 明确下载的代理与证书策略

这部分属于可靠下载的边界设计，应与兼容性一起验证。

- NONE 目前被转为空字符串，下载函数不显式设置 CURLOPT_PROXY；有代理环境变量时，libcurl 仍可能继承环境代理。应区分强制直连、继承环境和显式代理。
- [下载公共设置](../src/handler/webget.cpp) 无条件关闭 HTTPS 证书与域名验证。它与输出节点的 skip-cert-verify 是两个概念。若改为验证证书，需要同时考虑 Windows 信任库、代理 CA 和可定位到特定源站的例外。
