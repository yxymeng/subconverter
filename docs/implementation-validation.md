## 性能对照

Linux、本地 HTTP、每份规则 50ms 固定延迟、每个条件 3 次，取墙钟时间中位数。串行对照使用同一新实现的 async_fetch_ruleset=false；并行设置 true，下载上限 4。不是原版本与新版本的公网实测。

采用实际 Clash.ini 的 25 个远程条目及原始匹配顺序；7 个本仓库规则原文共 3,557,593 字节，其余源用单条模拟规则替代。一个模拟 Trojan 节点。生成 104,861 条规则，输出 5,406,928 字节；所有模式/缓存状态的输出 SHA256 相同。来源 SHA256 和规则仓库提交保存在 [原始数据](benchmark-linux.json)。

| 状态 | 串行 ms | 4 路并行 ms | 每次网络请求 | 下载字节 |
| --- | ---: | ---: | ---: | ---: |
| 冷缓存 | 1373.1 | 640.3 | 27 | 3560276 |
| 有效缓存 | 95.3 | 91.3 | 0 | 0 |
| 过期缓存 | 1371.5 | 642.9 | 27 | 3560276 |
| 主动强刷 | 1376.4 | 646.3 | 27 | 3560276 |

冷缓存并发模式的规则下载约 553.8ms，规则处理约 34.8ms。CPU 约 80ms、冷缓存采样峰值 RSS 约 38.2MiB，进程峰值 14 个线程（包括 HTTP 服务线程与下载池）。网络占主要等待时间，因此本轮没有增加处理结果或完整输出缓存。采样数值受调度、分配器和容器影响，不能作为内存上限；后续刷新阶段分配器保留内存较多，见原始数据。

复现：

```sh
python3 tests/benchmark.py --binary build/subconverter --rules-repo /path/to/yxymeng.github.io --repeats 3 --output benchmark.json
```

此脚本只读取已有公开规则 checkout，不拉取其他项目。Windows 可运行同一脚本；/proc CPU/RSS 采样仅支持 Linux，Windows 对应数据为空。

## 验证边界

- 未使用私人订阅，未在用户 Windows 机器上测量首次转换。Windows 静态代理代码需 Windows 发布检查及实机验证，PAC/绕过列表未支持。
- Docker 构建命令已经执行，但 Docker Hub 对 debian:bookworm-slim 的 manifest 请求返回 429 Too Many Requests；未进入编译或转换测试阶段。本轮没有成功镜像产物。
- Docker 改用 Debian bookworm；源依赖固定，系统包仍依赖发行版仓库，故不能承诺逐字节可复现镜像。实际系统包版本写入镜像。
- TLS 下载证书校验仍是上游既有策略；协议字段保真、rule-providers、持久订阅管理属于路线后续候选。
- 手动旧规则是文件级缓存选择，可能包含不同文件最后成功更新时间；没有历史整份配置回滚界面。
